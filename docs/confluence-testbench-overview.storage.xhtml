Implemented testbench: physical setup and software

This section records the bench as implemented. The laptop reads the ATI force/torque sensor over EtherCAT and the ESP32-S3 temperature/control subsystem over USB serial.

Physical connection chain

LaneConnectionPurpose
Load cellDedicated Windows laptop - USB 2.5 GbE adapter - PoE switch - custom Palm/ATI bench cable - EFlex Palm and ATI F/T sensorEtherCAT process data: Fx, Fy, Fz, Tx, Ty, Tz
Temperature/controlLaptop - USB serial COM33 - ESP32-S3 - sensor strip/OLED/Peltier driverTemperature telemetry, motion indication, thermal commands and local status

Custom cable: the conductor pinout is not stored with this project. It is a controlled bench harness, not a generic Ethernet/PoE cable. Use the released harness drawing or verify the existing cable before reproducing it.

Bench hardware

  • Dedicated laptop: runs the Python GUI, pysoem EtherCAT master, serial monitor, plots and CSV capture.
  • USB Ethernet adapter: dedicated Realtek 2.5 GbE interface selected by the GUI.
  • PoE switch and custom cable: provide the network/power path to the Palm and ATI load cell.
  • ATI EtherCAT F/T sensor: six-axis force/torque source. The current decoder reads six little-endian signed 32-bit values from the first 24 PDO input bytes. Confirm calibration/scaling before formal measurements.
  • ESP32-S3: reads two LTC2990 devices and an accelerometer, updates the OLED/LEDs, and controls mutually exclusive heat/cool request outputs.
  • External Peltier driver: accepts active-high HEAT and COOL logic. The ESP32 does not drive Peltier power directly.

Valid outputs are: both low = IDLE; GPIO13 high = HEAT; GPIO14 high = COOL. Firmware prevents both outputs from being high and inserts a 500 ms all-off interval before reversing direction.

Python GUI

  • Live: force, torque and thermal plots.
  • Analysis: saved-data review and thermal-drift characterization.
  • Serial Monitor: ESP32 telemetry, manual controls, Hold/Cycle settings and thermal state graph.
  • Hold: one target, idle window and sensor source. Target can change while running.
  • Cycle: alternates high/low targets on fixed timers and does not wait for measured temperature to reach either target.
  • Thermal graph: temperature versus time, dotted target/window lines, and red/gray/blue HEAT/IDLE/COOL history.

Startup checklist

  1. Keep external Peltier power off.
  2. Connect the EtherCAT chain and ESP32 USB cable.
  3. Confirm the USB Ethernet adapter and COM33 appear.
  4. Start the GUI and connect the ESP32 serial port.
  5. Confirm both LTC2990 devices report GOOD.
  6. Confirm thermal state is IDLE, then enable external Peltier power.
  7. Connect EtherCAT and verify a nonzero working counter.
  8. Enable CSV logging before the test run.

Safety and limits

  • GPIO13/GPIO14 are logic signals only. Use external isolation, pull-downs, current protection and over-temperature cutoff.
  • The software interlock does not replace hardware prevention of simultaneous Peltier polarity commands.
  • The GUI target range does not certify the fixture, Peltier, adhesive, sensor or test article for that temperature.
  • COM33 and the adapter name are machine-specific.
