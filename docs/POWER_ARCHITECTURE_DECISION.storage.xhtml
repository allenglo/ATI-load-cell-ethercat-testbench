Decision

Use a modular three-node power architecture: 24 V PSU input, battery, and protected load bus. Do not make one IC responsible for the charger, BMS, fuel gauge, programmable output and every optional interface.

The preferred battery/UPS baseline is BQ25756 + independent BMS and fuel gauge + protected PSU-to-load path. Add the programmable lab output as a separate power stage. USB-C PD is an optional port subsystem, not a prerequisite for the base platform.

Required system

  • 24 V PSU input.
  • Configurable 24 V-class battery pack.
  • Protected load bus that remains powered during input loss.
  • Battery charge and battery-to-load UPS operation.
  • Battery percentage, remaining capacity, health and fault reporting.
  • Per-cell monitoring, balancing and hard battery protection.
  • At least 10 A capability on the internal/output bus; USB-C remains limited by its negotiated contract.
  • Optional USB-C PD input/output at 140 W or higher using standard EPR.
  • MCU/I2C/SMBus control of voltage, current limits and telemetry.
  • Medical-robotics isolation and fault containment.

Architecture

24 V isolated PSU --> protection / ORing --> protected LOAD BUS --> robot loads
                                                |       |
                                                |       +--> programmable 0-24 V output
                                                |
                                               +--> BQ25756 bidirectional stage -- BATTERY
                                                                                  |--> BMS
                                                                                  +--> fuel gauge

Optional: protected load bus --> USB-C PD EPR source module --> USB-C port

The PSU-to-load path is external to the charger IC. It must provide reverse-current blocking and controlled source/battery arbitration.

  • None of the charger or PD controller candidates is a complete per-cell BMS and accurate coulomb-counting fuel gauge.
  • RAA489118 and RAA489400 are not a complete BMS/SOC solution.
  • PMG1-B2 has MCU and ADC resources but is not a turnkey independent safety BMS or calibrated fuel gauge.

Expanded design basis

This section expands the concept selection for a digitally managed 24 V-class power platform. USB-C PD is an optional add-on; the primary design problem is a protected PSU/battery/load system with measurable SOC and a separate programmable output.

Three electrical nodes

24 V PSU input ---- protection / ideal diode / ORing ---- protected LOAD BUS ---- robot loads
                                                         |                 |
                                                         |                 +-- programmable output
                                                         |
                                                         +-- bidirectional battery stage ---- BATTERY
                                                                                              |-- BMS
                                                                                              +-- fuel gauge

With the PSU present, its protected path supplies the load while the charger replenishes the battery within the source power budget. When the PSU is absent, the battery stage must regulate the load bus without backfeeding the failed input. The charger is only one branch of this three-node system; external ORing, hot-swap/precharge, reverse blocking and state control are still required.

Candidate ranking

  1. BQ25756 + PD controller + smart BMS/fuel gauge — 4.2/5 for the charger-platform option. Most mature high-voltage I2C battery stage in this set; add the independent BMS/gauge and external three-node power path.
  2. PMG1-B2 + smart BMS — 3.6/5. Most integrated digital PD/charger platform, but its firmware and validation burden is higher. Manufacturer reference materials describe 240 W sink capability; the listed reference design sources 27 W, so do not assume a 140 W source implementation without a matching design.
  3. RAA489118 + RAA489400 + smart BMS — 4.0/5. Attractive SMBus solution for a pack with comfortable margin below 30 V. A full 8S LiFePO4 pack reaches about 29.2 V, leaving little transient headroom; treat 6S/7S or a lower-voltage configuration as the better fit unless Renesas confirms the exact use case.
  4. ISL81601 / LT8708 — 1.4/5 under the digital-control requirement. Excellent power-stage flexibility, but analog control loops and external supervisory hardware conflict with the no-analog-command preference.
  5. BMS-first modular system — 4.7/5 as a system strategy. Not a charger substitute. It best covers SOC, SOH, balancing and independent pack safety when combined with a charger and output stages.

Battery safety and SOC component starting point

Cell monitor and protection: TI BQ76952

BQ76952 is a concrete candidate for a 7S/8S LiFePO4 pack: TI lists 3–16 series cells, I2C, cell-voltage measurement, temperature inputs, open-wire detection and cell/pack protection functions. It supports cell-balancing control; balancing resistors/FETs, heat dissipation, pack switches, fuse and fault response remain part of the pack design. Treat it as a monitor/protector, not the finished battery pack or a fuel gauge.

Pack fuel gauge: TI BQ34Z100-R2

BQ34Z100-R2 is a concrete pack-level fuel-gauge candidate. TI lists LiFePO4 chemistry, I2C and Impedance Track; the BQ34Z100EVM supports 1S–16S pack evaluation. It needs a correctly placed bidirectional current shunt and pack-specific configuration/learning. Validate SOC accuracy over the selected cell count, current range, temperature and aging profile before using SOC for safety decisions.

The charger, BMS and gauge have distinct jobs: BQ25756 manages charge/reverse conversion and converter telemetry; BQ76952 monitors individual cells and provides independent pack protections; BQ34Z100-R2 estimates remaining capacity. Coordinate pack-current sensing and calibration across them. The BMS hard cutoff must remain independent of MCU software and fuel-gauge accuracy.

Medical isolation and fault containment

Power components do not make a medical system compliant by themselves. The required isolation classification and leakage-current limits depend on intended use, applied-part classification, patient connection, operator access, enclosure and the system risk analysis. The safety/compliance owner must set those requirements before choosing an isolation barrier.

  • Start from an appropriately certified isolated PSU. Select required MOOP/MOPP barriers from the product risk analysis, not by copying a generic reference design.
  • Keep the battery BMS local to the pack. For communication across module/chassis domains, consider isolated CAN, for example TI ISO1042, with a separately designed isolated-side supply.
  • Review USB-C shield/VBUS, Ethernet shield, debug connectors, external DC outputs, heatsinks and chassis as possible paths across isolation boundaries.
  • Provide fuse, reverse-current blocking, surge protection, hardware current limit, thermal cutout and output disconnect independently of MCU firmware.
  • On MCU reset, communication loss or invalid telemetry, define a hardware-enforced safe state: charger/output disabled or bounded by independent protection.

Efficiency: BQ25756 versus ISL81601

A controller-only efficiency ranking is not valid. Both are four-switch bidirectional buck-boost controllers using an external power stage. The MOSFETs, inductor, shunts, switching frequency, dead time, layout, gate drive and thermal design dominate the result. BQ25756 prioritizes charger policy/I2C integration; ISL81601 offers independent input/output voltage and current loops. Neither fact alone establishes higher efficiency.

Compare real candidate boards at identical operating points: 24 V input to selected pack charge voltage, then battery-to-24 V load-bus reverse operation. Measure at 25%, 50%, 75% and 100% load, in both directions and after thermal equilibrium. Record calibrated Pin/Pout, frequency, FET and inductor part numbers, shunts, board temperature and airflow. Calculate eta = Pout / Pin * 100%. Compare both optimized implementations and, separately, a common-power-stage comparison if the controller interface permits it. Use the BQ25756EVM and an ISL81601 evaluation platform as starting points; do not compare peaks from different voltage/current conditions.

MCU and firmware approach

BQ25756 baseline

Use the system MCU as supervisor over I2C. It should own source-present detection, input power budget, charger voltage/current targets, reverse-mode transitions, load priorities, low-SOC derating, fault logging and controlled recovery. A general-purpose MCU from the existing product family may be suitable, but select it after I2C isolation, watchdog independence, ADC needs, lifecycle and safety analysis are defined.

PMG1-B2 option

PMG1-B2 combines USB-C PD and a 55 V buck-boost charging controller with an on-chip Cortex-M0 and peripherals. Development would use Infineon ModusToolbox and the PMG1 SDK: configure the PD stack, charger profile, battery limits, state transitions and fault handling, then validate against the specific reference board. Keep a separate BMS for cell protection. PMG1-B2 is attractive when integration is more important than reusing the external system MCU.

10 A programmable output stage

First controller candidate: TI LM51772. TI lists a 3.5–55 V input, 3.3–55 V output four-switch buck-boost controller with I2C. It is a controller with external FETs, not a turnkey 0–24 V/10 A supply. Its published EVM is a 9–48 V to 20 V, 5 A example; the 240 W target therefore requires a new thermal/power-stage design and validation. Confirm the I2C register map supports the desired voltage/current-limit commands and define a separate output-disable state below the 3.3 V regulation floor.

Do not use TPS55288 for a 24 V output: its specified output maximum is 21.26 V. For any 10 A design, separately size the MOSFETs, magnetics, shunts, connectors and copper for continuous current, then add hardware current limit, short-circuit response, thermal sensing, reverse-current protection and output disconnect. A software setpoint is not a substitute for these protections.

USB-C PD is an optional module

The base platform should operate from the 24 V PSU and battery without USB-C. If 140 W PD EPR is added, it requires an EPR-capable source/sink controller, a protected 28 V/5 A rail, VBUS discharge, cable validation and power-budget policy. Multiple ports need separate port power paths and an explicit shared-power allocator. Dell 130 W and other vendor-specific behavior is an interoperability target, not a guarantee of standard PD.

Open design work

  1. Freeze battery cell count, chemistry, charge ceiling, capacity and peak/continuous current. A 7S LiFePO4 pack leaves more margin below 30 V; retain BQ25756 if full 8S/29.2 V operation is required.
  2. Select and evaluate BQ76952 plus BQ34Z100-R2, including balance-network thermal design, pack-current shunt placement and SOC-learning plan; compare against traceable smart-BMS modules.
  3. Prototype BQ25756 and ISL81601 on evaluation platforms at matched operating points before making an efficiency claim or committing to the alternative.
  4. Prototype LM51772 as the digitally programmable load-output controller; prove 24 V/10 A thermal operation and hardware protection.
  5. Define and test three-node transitions: PSU present, charging, battery backup, source return, low SOC, BMS trip, output short and MCU reset.
  6. Set isolation/leakage requirements with the safety owner; document barriers and test evidence for every external connector/domain.
  7. Add USB-C only after the core PSU/battery/load and programmable output stages are stable. Validate each PD port/cable/contract with a protocol analyzer.
